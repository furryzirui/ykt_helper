# iOS 后台自动化验收

本版提供静音音频、画中画、持续定位和 iOS 26 限时课堂监控实验方案，并保留系统短时后台收尾。方案只能在应用前台启动；重复开启不延长已经设置的绝对截止时间。系统中断、画中画关闭或定位权限撤销后停止对应方案，开关应同步关闭。

这些方案不保证整节课持续运行，也不能保证在强行关闭、系统终止、重启后恢复。定位方案会增加耗电，需要“始终允许”；设备坐标不保存、不记录、不上传，不参与雨课堂位置签到。画中画显示本机时钟，关闭或暂停画中画即停止此方案。

静音音频使用允许与其他音频混音的会话，不设置 Now Playing 信息，不尝试清除其他应用的媒体状态。这既不保证后台自动化持续执行，也不保证系统在所有机型上隐藏本应用的媒体显示；仍需观察真实课堂心跳和答题记录。

到期时，iOS 在前台仅停止保活服务，应用仍可正常使用；在后台停止保活及自动化，把后续挂起交给系统，不主动结束应用进程。

iOS 26 限时课堂监控每次需手动开启，不支持永不关闭或自动重新提交。系统显示“后台运行中”和实际已运行时间，每 10 秒按经过时间更新会话进度；这不表示题目、AI 或 CPU 工作完成度。Apple 要求持续任务具备明确目标和准确进度，未明确认可限时网络监控作为通用保活用途；该方案需实测，可能被系统拒绝或提前取消，不保证所选时长。

## 真机步骤

1. 使用保留 `audio`、`location`、`processing` 后台声明和定位用途说明的签名安装包，在设备首次解锁后登录。关闭电脑调试器连接，分别在 Wi-Fi、蜂窝网络下检查。
2. 对每种方案分别确认说明并开启，验证实际资源已启动才显示开启。拒绝权限、关闭系统定位、禁止画中画时，应给出原因且不能显示已开启。
3. 持续定位先允许使用期间，再升级为始终允许。选择“仅允许一次”“保留使用期间”或拒绝时，申请应能结束，不无限加载；在权限页核对系统实际状态。
4. 锁屏或切换其他应用 5、15、45 分钟，观察真实课堂连接与签到、题目发布、自动填充、延迟提交及服务端答题记录。仅原生资源存在或开关开启不能作为自动化成功证据。
5. 分别在前台和后台等待短截止时间到期：前台只释放保活资源，应用仍可操作；后台释放保活资源并停止自动化，由系统挂起，不主动退出。再次开启或返回前台不能偷偷延长。调整系统时钟向前、向后，验证绝对时间或同进程单调计时先到者生效，原生最多每分钟重查一次；系统挂起导致回调延后时，回前台应立即校验并释放保活资源。
6. 测试来电、其他媒体播放、关闭或暂停画中画、撤销定位权限、断网重连与手动停服；资源释放后应同步实际状态，不自行重新开启。切换方案后旧方案资源必须释放。
7. 系统短时方案只检查有限收尾与到期停止，不据此判定整节课后台可用。强行关闭和重启单独记录为平台限制。
8. iOS 26 限时监控需检查每次手动开启、有限时长、系统实时活动的已运行时间及取消按钮。系统忙碌、后台刷新关闭或不支持的系统版本应明确失败，不能显示服务已开启。取消后不得自行重提；延长或缩短时长后，总时长与进度应对应真实会话。强行从多任务界面关闭会取消任务，系统不保证发送取消回调。

## 自行签名时的任务标识

若签名时修改 Bundle ID，需在**最终签名前**同步主应用 `Info.plist` 的这两个字段：

- `CFBundleIdentifier`：签名安装后实际使用的 Bundle ID，例如 `com.example.ykt-helper`。
- `BGTaskSchedulerPermittedIdentifiers`：数组中的课堂任务标识改为同一 Bundle ID 加 `.classroomMonitoring.*`，例如 `com.example.ykt-helper.classroomMonitoring.*`。保留数组中其他用途的任务标识。

签名工具最终使用的 Bundle ID 必须与这两个字段一致；构建后的 IPA 已展开 Xcode 变量，不能只修改源码中的变量名，也不能保留旧 Bundle ID 前缀来绕过检查。签名后再修改 `Info.plist` 会破坏签名。应用会在注册前核对配置，不一致时显示重签说明；通过配置检查仅表示标识匹配，系统仍可能拒绝或取消任务。

系统提交错误保留 `BGTaskSchedulerErrorDomain` 与错误码，并给出对应原因。重点记录配置不匹配、注册失败、代码 1（后台任务不可用）、代码 3（权限或声明不允许）与代码 4（暂不能立即执行）的差异，不以通用“启动失败”代替；不会显示系统错误中的任意详细信息或路径。

## 临时测试日志

手动构建附加 `--dart-define=YKT_IOS_BACKGROUND_DIAGNOSTICS=true`，或手动触发工作流并开启对应输入；默认构建关闭此日志，正式发布不得开启。

开启系统服务后，每 10 秒实际执行一次 Dart 心跳，再读取原生快照：静音音频显示播放状态与循环内播放位置，画中画显示激活状态与累计送帧数。心跳表示该时刻 Dart 确实执行；快照只反映当时原生资源状态，均不保证未来持续运行或真实答题成功。挂起期间不补造历史采样，检查前后台时间戳间隔；停服后停止采样。

日志仍仅保留最近 500 条，约可覆盖 40 分钟采样，课堂事件较多时更短。可在应用日志页导出后比较锁屏、来电及其他音频播放期间的记录。正式构建不产生此采样，也不恢复旧测试事件。

## 本地检查边界

Windows 工作区仅完成属性列表解析、Xcode 源文件登记和通道静态检查；Swift API 已对照 Apple 文档。macOS 可运行 `bash scripts/ios/test_continued_policy.sh` 检查原 ID、仅改 ID、同步白名单及错误信息脱敏。iOS 编译需 macOS CI 和 Xcode 26 或更新 SDK，运行下限仍为 iOS 15，限时课堂监控单独要求 iOS 26。Flutter 后台定时器、WebSocket 和真实提交需上述真机验证。不得将静态检查或编译成功写成后台运行验收通过。

参考：[Apple 持续任务文档](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)、[WWDC25 后台任务](https://developer.apple.com/videos/play/wwdc2025/227/)。按 [Apple 标识符约定](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtaskrequest/init(identifier:title:subtitle:)) 为每次会话分配独立标识符，拒绝已取消会话的迟到回调。此方案只使用 CPU 和网络，不申请后台 GPU 权限。
